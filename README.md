# Codex QQ Bridge

两台设备现在可以在配对 QQ 私聊中协作。一端给出初稿和要查证的问题，对端回传独立证据；发起端据此修订，并把同一份终稿交给双方。支持处理中补充、立即收件回执及断线后的恢复。[双端协作与真机验收](collaboration/README.md) · [Windows 私聊适配](windows/README.md)

配对端还可以用 `collab_write` 共写短稿。发起端写首段并指定缺口，对端按分工撰写正文。发起端合稿并提出结合两端材料的结论，对端校稿后可以确认或退修。[共写与退修](collaboration/README.md#配对私聊共写短稿)

在绑定群中，控制者从成员列表 @ 本机账号即可聊天。之后也可直接使用 QQ 的“回复”引用该账号的一条已核验答复或任务回执。普通群消息不会启动对话。[Mac 配置](macos/README.md#群内点名建聊) · [Windows 配置](windows/README.md#群内点名建聊)

## 群里什么时候开新聊天

群聊对话使用该账号、控制者、绑定群独有的 SQLite 记录重建短期记忆，每次在隔离、只读的 Codex 环境回答，能看到最近的公开交流、工作状态和已回群的正文。它有独立的接话线程；即使四个工作线程都在忙，也可处理新的提问。同一群的接话按收到的消息排队。持久工作聊天保留自己的任务目录、工具和上下文。

| 群消息 | 处理方式 |
| --- | --- |
| `@Mac 冷启动是什么意思？`，或引用答复问“为什么这么算？” | 群聊助手直接作答。 |
| `@Mac #42 进度怎么样？` | 从本机任务库返回阶段和最近的执行活动。普通状态查询可直接由桥接回答。 |
| `@Mac 帮我写一份周报`，或 `@Mac 执行：整理今天的决定` | 确认派工后发送含任务号的收件回执，在独立工作对话执行，最终再回群。用“执行：”可以明确派工。 |
| 引用任务回执说“把预算改成 350”，或 `继续 #42，把结论缩成三句` | 更新同一工作聊天。运行中尝试把补充提交给该轮次；已结束或服务明确拒绝时在原聊天开下一轮。结果不明时保留记录。 |
| `基于 #42 的终稿另开，写客户邮件` | 创建独立工作聊天，带入所指版本的已发布稿件。 |
| 任务号冲突，或有多个可能的目标 | 回群询问。引用澄清问题并指定任务号即可继续。 |

群里使用的编号是回群首行 `回复 #42` 的群序号。接话默认只面向已绑定的人类控制者；其他人或其他账号的答复不会触发机器人互聊。可在群里用“协作 UUID 的进度？”查询已配置的本机配对协作库，回复只包含阶段。群内修改针对本机群任务，配对共写修改仍通过该协作轮次的原入口提交。
