# Codex QQ Bridge

两台设备现在可以在配对 QQ 私聊中协作。一端给出初稿和要查证的问题，对端回传独立证据；发起端据此修订，并把同一份终稿交给双方。支持处理中补充、立即收件回执及断线后的恢复。[双端协作与真机验收](collaboration/README.md) · [Windows 私聊适配](windows/README.md)

配对端还可以用 `collab_write` 共写短稿。发起端写首段并指定缺口，对端按分工撰写正文。发起端合稿并提出结合两端材料的结论，对端校稿后可以确认或退修。[共写与退修](collaboration/README.md#配对私聊共写短稿)

在绑定群中，控制者可以用 `/task` 创建本地工作聊天。启用群 @ 功能后，从 QQ 成员列表点名本机协同账号并附上任务，可以新建或续接一个持久聊天，桥接将这次点名对应的最终答复发回原群。[Mac 群 @](macos/README.md#群内点名建聊) · [Windows 群 @](windows/README.md#群内点名建聊)

## 群里什么时候开新聊天

在绑定群里从成员列表 @ 本机协同号。桥接按本账号与群内的原任务序号或原生引用定位，按每条新消息 ID 去重。群里使用的编号就是回群答复首行 `回复 #42` 中的 `42`。桌面手动追加的回合留在本地。配对私聊共写、审稿继续按轮次 UUID 跟进。

| 控制者的操作 | 预期行为 |
| --- | --- |
| 从成员列表 @ 设备，提出独立任务 | 创建新聊天。复用相同的本机角色说明。 |
| 引用该设备先前的回群答复并再次 @ 它，或写“@设备 继续 #42，把结论缩成三句” | 按原答复或原任务群序号定位聊天，在同一工作目录开下一轮。只回传这一轮的终答。 |
| 在没有引用的情况下只说“继续刚才那个”，且无法唯一定位 | 请控制者引用原回复或给出任务号。同群可能并行处理多项工作，优先用明确的引用。 |
| 明确要求参考旧成果另做一件事，如“@设备 基于 #42 的终稿另开，写客户邮件” | 创建新聊天，并带入被指定的已公开终稿或摘要。旧任务仍可单独追问。 |

遇到多个编号、号码查不到、引用其他人的消息或与正文冲突时，会在群里询问。可以引用这条澄清消息，再 @ 本机并回答“继续 #42”，分发器会带回之前待确认的要求。引用预览中的文字不参与识别。记录每条来源消息对应的聊天、轮次和回群回执，同一聊天的追问依次处理；群消息重投或进程重启时，按原记录恢复。创建或投递结果无法核实时保留原记录供核对。聊天多久没动过都不影响明确引用。
